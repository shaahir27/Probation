## P03 — Egress redaction and bounded context

Files: `llm/redact.py`, proposed context/reader/gateway modules, pack adapters, bounded HistoryView helpers and exposure paths.

1. Reconstruct current-item context through bounded source access. Mail includes separately redacted subject/body and display-name information needed locally, sender-domain class and approved deterministic metadata. Invitations include redacted title/description, organizer class, duration and start bucket. Never send addresses, native resource credentials, raw private URLs or a full history object.
2. Pass actual header display-name tokens and configured owner tokens into local redaction. The captured mail/calendar callers omit display_names; existing redacted_text also loses its map/counts. A column named redacted_text is not an egress guarantee, especially for files/Radar/Reading.
3. Introduce an explicitly scoped redaction context for multipart jobs. Keep each document's token namespace disambiguated in examples/current input, or share a reviewed request-local namespace with equivalent privacy tests. PROMPTS currently specifies per-document numbering: update that format decision explicitly rather than changing restoration semantics invisibly.
4. Restore only allowed PERSON tokens tied to the current reply parties/owner. Never restore EMAIL/URL/OTP/card/UPI/IFSC placeholders. Historical example names cannot become new reply recipients or be restored blindly. Literal placeholder-looking input must not forge restoration authority. No map is sent to a provider or written into exposure/ledger data.
5. Test replacement ordering: URLs containing person-name tokens, overlapping sensitive patterns, signatures, quoted history, mixed case, repeated values, international numbers and preserved dates/amounts. Current same-class URL map keys overwrite each other; do not use that map to restore URLs. Define counts as replacements in actually sent content, not guessed zeros or unique values mislabeled occurrences.
6. Bound file context to the allowed filename/textual snippet contract. Do not open arbitrary downloaded files/programs for more context. Bound incoming/exam/quarantine/example fields separately and the final request as a whole. Truncate before wrappers with deterministic boundary rules; do not cut placeholder/tag syntax in half or hide truncation from provenance.
7. Apply the same guarantee to writer examples, owner-edited text if later used in LLM jobs, exam edits, wording, synthesis specifications and quarantine pages. Raw web text may reach only a quarantined extractor after applicable minimization; it never reaches writer/policy prompts. Quarantine source-support validation can use the original local page and a controlled span mapping.
8. On redaction/context failure, return a safe typed status; do not retry unredacted. Log job/request IDs, counts and safe error codes only. Do not log raw exception strings, provider bodies, prompts, restored text, token-bearing URLs or maps.

Tests/evidence: W3-T09-T13/T25/T29. Capture outbound MockTransport requests for every job family, including malicious delimiters/placeholder injection and multi-example name collisions. Deterministic-only optional files still work without any outbound request. Output: privacy contract, fixture matrix and measured counts; redaction remains best effort, never described as anonymisation.

## P04 — Durable reservations and attempt accounting before concurrency

Files: proposed `db/budget.py`, reviewed migration/model files, `llm/budget.py`, `db/inference.py` and role ownership helpers. Exact DDL is a W3-D03 review gate.

1. Account scope must identify provider/account/budget/unit independently of replay/persona/run. New clients, workers, process restart or historical clock jumps cannot reset spend. Fake/cached evaluation accounting is distinguishable from real billed attempts; do not combine USD with Tavily credits.
2. Define separate immutable logical request and physical attempt identities. Proposed reservation/attempt data: ID, request digest, owner role, provider/budget scope, attempt ordinal, bounded estimate, state, reserved/charged amount, usage provenance, dispatch/reconciliation times, lease/fencing metadata and safe status. No request bodies or secrets in accounting rows.
3. Use reviewed integer monetary units/Decimal calculations; round upper-bound reservations conservatively and avoid repeated six-decimal downward rounding. Validate finite/nonnegative model rates and token limits. Missing/unverified/unbounded pricing cannot silently use cheap default rates.
4. Short atomic reservation transaction checks charged + held + ambiguous amounts against the cap, allocates the attempt and commits **before HTTP**. A process-local spent_usd float is not a reservation. Every retry, unsupported-format fallback and repair needs its own bounded authorization/accounting.
5. Record dispatch intent and reconcile actual usage/cost per attempt, including invalid model output and unsuccessful potentially billable responses. Missing usage uses the reviewed conservative bound with explicit estimated status; do not invent 800/150 tokens. If actual billing exceeds an estimate, preserve the charge, stop further dispatch and report it; do not assert a provider billing guarantee without bounded supported limits.
6. Never release an ambiguous dispatched attempt solely because a lease expired. A crash/timeout may already have incurred cost. Keep the bound charged/reserved until safe reconciliation or an authorized operator resolution. Requests known never dispatched can release; known free errors follow an explicit validated policy.
7. Preserve WP1's atomic cache-plus-exposure pair while making spend durability independent of proposal/cache rollback. The caller must finish the job's short accounting transaction separately from application inference persistence. No client helper commits someone else's active transaction; no SQLite write lock spans HTTP. Define ordering before adding a second writer call in the same proposal flow.
8. If a dedicated role connection to the same DB is used for durable accounting, prevent the caller from holding a conflicting write transaction first. Accounting failure denies outbound calls. The new schema's per-role row constraints must be enforced against actual SQL, not a trusted supplied table name. Avoid introducing a second per-user database against existing decisions without review.
9. Design operational timing separately from historical inference time through injected core Clock capabilities. Replay jumps cannot expire a live cost reservation/flight lease or move charges into a different budget period. No wall-time value enters features, exams or historical evidence.

Tests/evidence: W3-T14-T18/T31. Two independent processes/connections competing for the last budget unit, killed dispatch, failed reconciliation/persistence, duplicate attempt allocation and unavailable accounting store. Acceptance is prevented unauthorized dispatch under the tested bounded model, not a claim that arbitrary provider billing is exactly predictable. Output: reviewed state machine/migration, ownership tests, rollback/recovery runbook and denial reasons.

## P05 — Correct transport, error handling, semantic cache and single-flight

Files: `llm/client.py`, `cache.py`, `budget.py`, `db/inference.py`, proposed gateway/transport error types.

1. Keep schema compilation and cache revalidation before use. Registered job gateway rejects missing/unsupported production IDs/versions; generic diagnostic client schemas retain their explicitly supported WP1 behavior. Validate stub, cached and fresh outputs against the same current strict job model and contextual checks.
2. Build content_hash from the complete canonical semantic request envelope: rendered system/user inputs, examples/style/typed context, schema/template/context/validator versions, model/provider identity, relevant decoding/output limits and purpose. Preserve the contract's outer `(content_hash, prompt_id, prompt_version, model_id)` key. Never rewrite old cache rows to make incompatible data appear current.
3. Separate validated raw model-output cache from local restored draft storage. Cache hits do not create fake paid calls; report hit/reuse provenance separately. A usable cache must have the required accounting/exposure provenance. Failed validation is not permission to resend a private request automatically through another provider.
4. Implement per-key single-flight with a durable unique claim/fencing token if multiple workers are supported. Followers wait/read the winner's validated result or return safe unavailable; no arbitrary unbounded waiting. Expired/ambiguous claims require the P04 reconciliation policy, not an automatic duplicate paid request. Only claim owners can publish results. Never share a raw SQLite connection across worker threads.
5. Classify HTTP/auth/model/transport/refusal/format/validation/truncation failures. Only a recognized provider-specific unsupported-response-format rejection enables structured-format fallback. 401/403, unknown model, endpoint failure and exhausted 429/5xx retries cannot mark a model 'format unsupported' and start extra format calls.
6. Distinguish a successful HTTP response with invalid output from a transport failure. Enforce the reviewed one-repair limit; prevent structured invalid output -> fallback -> another repair from becoming an unbudgeted repair ladder. Bound the total attempt tree and record each stage.
7. Parse only nonempty final message content. Never accept reasoning_content as output; reject tool calls/refusals, missing choices and finish_reason truncation. If narrowly documented Markdown-fence extraction is retained, it cannot scrape arbitrary reasoning/prelude JSON. Keep schema and contextual validation mandatory after parsing.
8. Retry only approved transient failures, including the intended ConnectTimeout handling. Support bounded Retry-After seconds/date handling with injected timing; malformed or extreme values are bounded/denied. Seed any retry jitter and persistence ordering as required. Log typed codes rather than raw exceptions.
9. Centralize source settings and explicit transport authority. No literal writer/model_reader/Meta-Llama fallback IDs; no new endpoint. Reuse an owned HTTP/client lifetime where justified, close it correctly and keep independent role/budget state explicit. Existing allow_live_llm controls must not be bypassed merely by injecting a real client.

Tests/evidence: W3-T05/T08/T15-T18/T21-T24/T31/T35. Use fake HTTP with exact call counts for 401, unsupported format, 429, timeouts, malformed content, reasoning-only, truncated, refusal and failed repair. Test changed system/examples/style/schema/limits causing cache misses, unchanged complete requests hitting cache, and old cache incompatibility. Output: bounded request state machine, complete attempt accounting, safe errors and no silent endpoint/model fallback.

## P08 — Actual reply writer and local draft validation

Exclude system-generated replies, future decisions, weak similarity pretending to be strong linkage, undo labels and unapproved edited examples. Rank similarity with an approved already-provisioned local embedding path, or a reviewed deterministic fallback; no implicit model download/new dependency (WP4 interface dependency).
3. Generate only where the preview warrants a REPLY draft. The initial policy action/permission is unchanged by writer fluency. Structured ReplyWriter output is required; a missing/invalid writer cannot create an executable body. Chain REPLY calls this same service with the trigger's original source binding.
4. Apply schema and deterministic contextual validators: 5-1200 characters, original-sender-only recipient set by code, no unauthorized new URLs/addresses/attachments, unresolved placeholders rejected, amounts/payment claims checked against source, and unsupported dates/commitments handled conservatively. Validate before display/persistence and again where required at execution.
5. A regex cannot prove semantic faithfulness. Flag uncertain commitments/details for user input or reject the draft according to reviewed rules; never claim text is guaranteed truthful. 6. Permit at most the specified one draft regeneration, accounting separately from client JSON repair. Bound the full worst-case retry/regeneration cost tree. On exhaustion return ASK with draft_invalid/unavailable; no old unvalidated body is reused.
7. Restore permitted current-context PERSON placeholders locally after model-output validation, then validate the restored draft again for length/placeholders/content. Preserve redacted model-output provenance and local generated draft provenance; never put restored text in the cache/accounting/ledger that expects nonpersonal material.
8. Derive message/native thread, original sender/owner identity, recipient and draft references from server-owned source data. Replace proposal_parameters' unconditional REPLY draft_unavailable only when a validated draft is supplied.
