# EVALUATION_PLAN

How we generate practice data, what we measure, what we compare against, and how we report. Authority: below `CONTRACT.md`.
Numbers called **aims** are targets, not results. Report what we measure, including failures.

---

## 1. Questions the evaluation must answer

1. Does Probation need fewer interruptions than the alternatives **at the same low rate of costly mistakes**?
2. Do licences get earned quickly for frequent task types, and lost when habits change?
3. Does the exam catch a system that is only passing on shortcuts or tricks?
4. Are mined habits and chains correct?
5. What does it cost, how fast is it, and how much text leaves the machine?

---

## 2. Synthetic world generator

Implements `synth/`. Same seed gives byte-identical output (T-SYNTH).

### 2.1 Personas
- 20 personas: **15 development** (used for tuning) and **5 test** (never used for tuning; reported separately).
- Source: NVIDIA's open Nemotron-Personas-India dataset (check the licence on its dataset card). Fallback: 5 hand-written personas.
- Each persona has: a name, a role (student), writing style parameters (`greeting`, `signoff`, `median_words`, `formality`), a set of contacts (professors, friends, clubs, recruiters, services), and a set of origin sites for downloads.

### 2.2 Hidden habits (the answer key)
Each persona gets 10-15 rules drawn from a library of about 40 rule templates, with random parameters (response probabilities in `[0.85, 0.99]`). A rule is evaluated on the **attributes** of a situation (which the engine never sees directly; the reader must recover them from text).

Habit DSL example (`synth/habits_dsl.py`):

```json
{
  "persona_id": 1, "noise": 0.07,
  "rules": [
    {"id": "R1", "family": "email_action", "when": {"sender_role": "professor", "intent": "request"},
     "then": {"REPLY": 0.95, "LEAVE": 0.05}},
    {"id": "R2", "family": "email_action", "when": {"intent": "newsletter"},
     "then": {"ARCHIVE": 0.97, "TRASH": 0.03}},
    {"id": "R8", "family": "invite_rsvp", "when": {"start_hour_bucket": "early"},
     "then": {"DECLINE": 0.93, "ACCEPT": 0.07}},
    {"id": "R10", "family": "file_destination", "when": {"origin_group": "portal.college.example"},
     "then": {"MOVE_TO_FOLDER:College/Sem3/Lab": 0.97, "LEAVE": 0.03}}
  ],
  "chains": [
    {"trigger": {"family": "email_action", "sender_role": "professor", "has_deadline": true},
     "follow": [{"action": "REPLY", "p": 0.95},
                {"action": "BLOCK_TIME", "p": 0.85, "delay_hours": [2, 20]}]}
  ],
  "drift": {"at_day": 120,
            "changes": [{"rule": "R8", "then": {"ACCEPT": 0.80, "DECLINE": 0.20}},
                        {"rule": "R2", "then": {"ARCHIVE": 0.50, "LEAVE": 0.50}}]}
}
```

- The first matching rule (by order) decides the action distribution; a default distribution applies when none matches.
- **Noise:** with probability `noise` (default 0.07) the true action is replaced by a random other action.
- **Drift:** at `drift.at_day` (default day 120 of 180) the listed rules change.

### 2.3 Volumes per persona (180 days)
About 2,000 mails (roughly 40% automated), 300 invites, 600 files, and about 120 professor deadline mails that trigger chains. Total about 3,000 situations. A 14-day buffer at the end is censored (no outcome).

### 2.4 Content
- Mail and invite bodies: a **pool** generated by `synth.*` prompts (`PROMPTS.md` section 9), cached, then reused with code-side substitutions. Target pool size about 1,500 bodies (cost about $1 **(assumption)**).
- User replies (the "Sent" mails): built from code templates (greeting + one of about 20 acknowledgement sentences + sign-off in the persona's style). No LLM.
- Files: names and origin sites from templates per persona.

### 2.5 Rendering
Outputs the same formats real data would use: `.mbox`, `.ics`, a folder manifest plus a real directory tree, and `world.db` (`PACKS_SPEC.md` section 0.5).

### 2.6 Truth file
`truth.json`: per situation id, the attributes, the true action after noise, the rule id, and a `drifted` flag. **The engine must never read it** (static check in T-SYNTH). Only the evaluation harness reads it.

## 3. Metrics (exact definitions)

`N` = number of situations in the evaluated period. `A` = proposals auto-executed (`gate` in `EXECUTE_UNDO`, `HOLD_THEN_EXECUTE`, `EXECUTE_SILENT`). The truth file gives the persona's true action for every situation, **including the ones the system executed** (counterfactual truth, available only to the evaluation harness).

| Metric | Definition |
|---|---|
| **Agreement** | Share of strong-outcome situations where `action == observed_action`. Report with abstentions counted as misses, and separately among non-abstained |
| **Precision (class, action)** | `k / n` over the evidence set |
| **Autonomous error rate** | Among `A`: share where `action != true_action` |
| **Harm-weighted error** | `sum(loss(a) for a in A if a != true_action) / sum(loss(a) for a in A)` |
| **Autonomous coverage** | Among situations whose true action is not a no-op (not `LEAVE`, not `NO_RESPONSE`): share handled by `A` correctly |
| **Asks per 100** | `100 * #ASK / N` |
| **Suggestions per 100** | `100 * #SUGGEST / N` |
| **Attention units per 100** | `asks + 0.3 * suggestions` per 100 (the 0.3 is an assumption; vary it in a sensitivity check) |
| **Calibration error (ECE)** | 10 equal-width bins over `p_max`, strong outcomes only; also Brier score |
| **Days to first level 2** | Per family and per class: simulated days from the start until the first level >= 2 licence |
| **Licence stability** | Level changes per `(class, action)` per 100 days; **false demotions** are demotions with no drift in the truth file |
| **Drift detection delay** | Days (and situations) from `drift.at_day` to the first alarm on an affected class; **false alarms** are alarms in the 60 days before the drift |
| **Exam metrics** | Invariance flip rate; critical violations; pass rate; cheating-policy catch rate |
| **Chain quality** | Precision and recall of mined chains against planted chains (match on trigger class and follow action); follow-through rate of proposed steps |
| **Audit overhead** | `audits / (audits + executed)` |
| **Efficiency** | LLM calls per situation; tokens per situation; USD per 1,000 situations; reader latency p50 and p95; replay throughput (situations per second); policy fit time |
| **Privacy exposure** | Tokens of personal text sent per situation; share of situations with zero LLM calls (cache hits) |
| **Pack effort** | Person-hours to add a new pack (stretch pack) |

All metrics are computed by `eval/metrics.py` and tested on hand-computed fixtures (T-EVAL).

## 4. Baselines

All baselines see the **same situations in the same order** and obey the same no-peeking rule.

| ID | Name | Behaviour |
|---|---|---|
| **B0** | Majority class (sanity check) | Always predicts the most common past action for the family (no personalisation). Used only for the **agreement** metric, not for attention or autonomy |
| **B1** | Ask always | `ASK` for every situation (100 asks per 100, zero autonomy) |
| **B2** | Generic rules (not personal) | Mail: if `looks_automated` or intent in `newsletter, receipt, sales`: auto `ARCHIVE`, else `ASK`. Calendar: always `ASK`. Files: auto-move by file type to a fixed folder per `ext_group`, else `ASK` |
| **B3** | LLM-confidence threshold (simplified KnowNo style) | A Super call per situation receives the redacted text plus the 10 nearest past situations with their outcomes (no peeking) and returns `{"action", "confidence"}`. Act autonomously if `confidence >= tau`, else `ASK`. Sweep `tau` over `{0.50, 0.60, 0.70, 0.80, 0.90, 0.95, 0.99}` |

B3 is run on **2 personas** to control cost (about 6,000 calls, roughly $3 **(assumption)**).

| **E6** | Chains: discovery precision and recall; follow-through | Table |
| **E7** | Efficiency and privacy: calls, tokens, cost, latency, cache hits, exposure | Table |
| **E8** | Human study (optional, section 6) | Learning curves |
| **E9** | Pack effort: time to add the Radar and Reading packs | Hours |
| **E10** | Entity vetting accuracy (`TAVILY_AND_NEW_PACKS.md` section 14): about 60 legitimate domains, about 60 **fictional** lookalikes, about 20 invented organisations with no web presence; also the local brand list alone as a baseline | Confusion matrix per status; false-veto rate on legitimate domains; credits per entity; latency p50 and p95; cache hit rate |

Notes:
- Ablations reuse cached featurization, so they cost about $0 in LLM calls.
- "Matched operating point" means: for each method, the setting with the **fewest attention units** whose autonomous error rate is **at most 2%**. If a method cannot reach 2%, report its minimum error.
- Tune only on the 15 development personas. Report the 5 test personas separately.

## 6. Human study (optional)

**Purpose:** check that the engine learns from real human decisions, which are noisier than synthetic ones.

**Design**
- 6-10 classmates. Each sees the same pool of **150 synthetic items** (60 mails, 40 invites, 50 files, rendered realistically) and records what they would do (`REPLY/ARCHIVE/...`, `ACCEPT/DECLINE/...`, folder choice) in about 25 minutes.
- Their decisions, in a random time order, become that person's "history". Run the walk-forward replay on each person individually.
- Output: agreement as a function of the number of labels seen (learning curve), and whether any class would earn level 1.

**Ethics and privacy**
- Items are synthetic: no personal data in the stimuli.
- Obtain consent; store only an anonymous participant ID and the decisions; participants may withdraw.
- Do not collect real mail, files or calendars.

## 7. Reporting

- Files: `docs/results/main.json`, `docs/results/tables.md`, figures under `docs/results/figures/` (aggregates only; no per-item data).
- Figures: (1) risk-coverage curves for Probation and B3; (2) attention units versus autonomous error; (3) licence ladder timeline for one persona; (4) drift detection timeline; (5) cost and latency summary.
- Each result states: seed, personas, model names, prompt versions, date.
- 95% confidence intervals by bootstrap over personas.
- **Honesty rules:** state that data is synthetic; report negative results; do not call anything a guarantee; do not tune on test personas; keep the exact commands to reproduce.

## 8. Aims (targets to compare against, not claims)

| Aim | Target |
|---|---|
| Attention versus B3 at matched error | At least 30% fewer attention units **(assumption)** |
| Days to first level 2 for high-volume classes | 45 simulated days or fewer |
| Drift detection | Within 40 situations or 14 days of the change, with no false alarms in the 60 days before |
| Exam | Invariance flips 3% or fewer; zero critical violations for licensed classes; cheating policy caught 100% |
| LLM calls per situation | 1.0 or fewer on average |
| Reader cost | At most $0.10 per 1,000 situations (expected about $0.06) |
| Reader latency p95 | To be measured; set the aim after the day-1 spike |

---

## 8b. Tavily aims (targets, not claims)

False-veto rate on legitimate catalog domains 10% or less; `lookalike` recall on fictional lookalikes 90% or more (local list plus Tavily); zero decision flips under injection; at most 2 Tavily credits per newly vetted entity. Tavily credits are separate from the dollar budget below: about 240 credits to vet the catalog once, staying under the free 1,000 per month unless the Builders Program grants more.
