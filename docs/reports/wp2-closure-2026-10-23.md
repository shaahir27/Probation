## 1. What this pass was

WP2 had already been declared complete, and its build log asserted "Known issues/deferred: None".
Every finding below was first reproduced against the current working tree; several reported items
had already been repaired, and the ones that had not were fixed at the end that caused them rather
than at the symptom. The audit's most important result is not the defect list — it is that the
acceptance test for the package's central invariant could not see the class of leak it claimed to
catch, and had to be rebuilt and then proven against injected leaks.

## 4. Defects found and repaired in this pass

1. **`make check` failed before any other work.** The index added in the previous slice was
   collation-blind and unused by the hot paths; corrected, with a plan-cache regression.
2. **Resolvers could not see the fields they needed.** `resolve_outcome` did not pass the parsed
   raw payload, so the files resolver never got `rel_path` and the calendar resolver never got
   `uid`. Threaded through the shared internal helper, keeping the public `iter_situations(source,
   since)` signature as D5/CCR-E requires.
3. **Fabricated deletion evidence.** With no allowed root scannable, `resolve_files_outcome`
   concluded `STRONG DELETE` for every left-alone file. The policy then learned `DELETE` — an action
   the files pack cannot render — and every such proposal was correctly failed closed to ASK, so
   autonomy was never at risk; the crash was in the examiner. Now a search that never ran concludes
   nothing.
4. **`InvalidAction` aborted a replay.** `workers/drift.py` called `parse_action` on a stored
   proposal label with no guard. An unrenderable action is now reviewed (receipt written, so the
   class is never permanently denied) but excluded from the disagreement tracker.
5. **The V08 test could not see two of the three axes it claims to cover.** Rebuilt; see §5.
6. **C9, precisely repaired.** `resolve_mail_outcome` read the label state *as of now* — which in a
   full run is the year 2099, i.e. the end of the story — while stamping `known_at` at the response
   deadline, and fell back to the label set baked into the exported payload when the message was not
   in the world. It now projects at the window close and returns no outcome when no observation-point
   answer is available. The payload label set is untouched: it remains available to later resolution,
   it simply can no longer answer a question dated at the deadline. Deleting the labels was the wrong
   repair and was not done.
7. **The tracked fixture was silently stale.** It predated the identity, world and chronology work:
   no footprint stream, no state declaration, the wrong owner, calendar resolution at 0/28 and
   accuracy at exactly 0.0 while B0 scored 0.98. Regenerated (command in §7).

## 5. Proof that the acceptance test can see a leak

`data/audit/mutate_v08_harness.py` injects a real leak into the source, runs the test, and restores.
All four were caught; every file verified byte-identical afterwards.

| Injected leak | Caught by |
|---|---|
| World label projection ignores the observation point | `test_no_peeking.py` — the C9 mutation axis collapses to zero and the axis-coverage guard fires. Caught by the coverage guard rather than by a verdict difference, which is honest and is what the message says. |
| Resolver reads the final label state (no `as_of`) | `test_outcome_resolvers.py` — `'ARCHIVE' != 'LEAVE'`, and the fail-closed test returns an outcome where it must not. |
| Resolver reads "as of now" but dates the outcome to the window | `test_outcome_resolvers.py` — `'ARCHIVE' != 'LEAVE'`. |
| Replay stops filtering staged outcomes by the cut | `test_no_peeking.py` — "the horizon was not enforced; [situation] leaked past it". **This leak was invisible to the previous version of the test**, which compared only proposals and the ledger. |

## 6. Open items, stated plainly

1. **Executor world-writes are unattributed (plan 6.2.5). Needs a ruling.** `update_message_labels`
   and `update_rsvp` — the writers the pack executors call — mutate the same columns that
   `declare_initial_state()` declares to be the initial state, and record no actor. Verified today:
   the Executor creates no `user_actions` row and no outcome row, so no evidence is fabricated inside
   one run. The exposure is the second run: after Probation archives a message, an as-of read taken
   before that archive reports it as already archived, and a window that closes after an executed
   action reads Probation's own act as the owner's — the self-reinforcement the contract forbids.
   A backtest cannot reach it (every class in this corpus is at licence 0, so nothing executes).
   The fix is a dated, actor-attributed effect stream that projections may apply while resolvers can
   exclude — a world-model change with a wide blast radius, offered for a decision, not attempted
   here. No contract text was edited.
2. **The physical file scan is excluded from V08 by construction.** `resolve_files_outcome` reports
   a file's *current* location and stamps `known_at` at the window close, so scanning a real tree
   makes provisional LEAVE/MOVE judgements depend on when the test runs and a truncated run
   legitimately differs from a full one (measured: a mounted root adds 19 `files` outcomes and moves
   outcome totals from 181 to 200). This is a files-pack design question, not a leak.
3. **`FILES_WATCH_DIRS` is compared two ways.** Intake uses `Path(w).name.lower()`; the resolver's
   step 3 compares full relative folder paths, so an absolute configured watch directory never
   matches.
4. **23 chain follow-up proposals have no `features` row** (features 200, proposals 223). Their
   proposals are legitimate, but the missing vector means explanation and audit paths cannot re-read
   what they were built from. WP8's boundary.
5. **Evaluation inputs are WP10 work, not WP2**, and are untouched here: `eval/run_eval.py` resolves
   truth paths relative to the current working directory and returns `{}` when none exists; its
   `true_action` falls back to the prediction, so an unscorable record silently counts as agreement;
   the ablation table is literal constants; `mined_chains` and `planted_chains` are the same
   hard-coded object. Plan 14.1-14.2 assigns all of this to WP10. The one thing WP2 can say is that
   derived situations are declared and traceable, which is what 6.1.4 requires of this package.
6. **Unused code:** `HistoryView.get_prior_files_in_folder` and `get_prior_outcomes` have no
   callers; `packs/calendar/resolver.py` accepts `user_addresses` and never uses it.

first, and only then copied over the tracked files:

```
cd backend && rm -rf tests/fixtures/tiny_synth && \

  --persona-id 0 --seed 7 --size tiny \
  --out ../backend/tests/fixtures/tiny_synth --overwrite --regenerate-fixture
```
