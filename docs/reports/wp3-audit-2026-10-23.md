## 3. Existing protections to preserve

- Strict Pydantic job forms and provider schema compilation, including rejecting extra fields/nonfinite values; cache payloads are revalidated. Generic schema utility support must not become a permissive production job catalog.
- Immutable proposal/draft checks and the Brain-owned ledger then proposal then draft savepoint. Existing rollback/idempotency and role-denial tests are important evidence to retain and rerun later.
- Case-preserving parsed actions, pack descriptors separated from executable adapters, append-only ledger enforcement and centralized Clock from WP1. New adapters cannot bypass those boundaries.
- WP2's explicit allow_live_llm, reusable client injection and event-time HistoryView. Accidental paid model use must not return through new gateway defaults.
- Safe draft_unavailable/recipient_required outcomes. Reachability of a REPLY path is not sufficient reason to enable sending before trusted draft consumption exists.
- Existing quarantine stores/strict forms and code verdicts. Models supply data; code validates/verdicts. Do not move raw page text into the writer or policy to make integration easier.
