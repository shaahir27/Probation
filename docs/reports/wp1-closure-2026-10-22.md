## Operation and migration

For an existing engine database, the operator runs `probation db migrate` through the
bootstrap/admin boundary before starting the new API/workers. Fresh `probation db init`
includes the additive upgrade. API returns 503 with upgrade guidance if tables are absent.
No existing/private user database was opened or migrated during implementation.

`probation examiner-tick` drains bounded outcome/correction review and administrative
commands using a dedicated Examiner connection. Nightly review also drains them before
derivation. HTTP mutations return `{ok, command:{id,kind,status,requested_at,updated_at,result}}`;
`GET /api/commands/{id}` reads status. Retrying the same payload uses the original command;
a deliberately new exam uses an explicit new `attempt_ordinal`.

Exam computation runs before command completion, outside a command transaction.
Its stable persisted result closes the crash gap without claiming atomic network I/O.
The durable multi-worker supervisor, billing reservations and full connector leases
remain later work-package responsibilities.
